# ADR-0003: LXC system container

Status: **Proposed**

Date: 2026-09-05

## Context

Android needs PID1 and a system userspace while sharing the host kernel. Namespace isolation alone does not supply mobile boot/HAL/LSM assumptions.

## Decision

Use LXC7 on the reference host, with a private instance per Linux UID and subordinate UID/GID mappings where feasible. A privileged helper owns validated configuration, mounts, devices and lifecycle tools. Android init remains container PID1 after a documented container boot adaptation.

## Alternatives and consequences

Alternatives are systemd-nspawn or an OCI runtime; neither solves SELinux or HAL compatibility. Do not write a custom container runtime. No VM, per-APK container, guest host-network namespace, broad capabilities or arbitrary hooks. Android AID range and APEX/netd operations may require changes.

## Evidence and validation

[L01, A11, K05](../SOURCES.md); [SPIKE-001](../SPIKES.md#spike-001), [SPIKE-009](../SPIKES.md#spike-009), [SPIKE-010](../SPIKES.md#spike-010). Accept after boot and privilege audit, not merely lxc-start success.
