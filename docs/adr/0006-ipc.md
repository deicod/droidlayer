# ADR-0006: Linux Unix sockets and explicit resource protocol

Status: **Proposed**

Date: 2026-09-05

## Context

DroidLayer needs lifecycle/metadata and FD transport, without coupling host control to Android Binder internals.

## Decision

Use private pathname AF_UNIX SOCK_SEQPACKET endpoints and SCM_RIGHTS. Separate bounded control and frame channels. Use versioned headers, request/event sequences, instance/task/buffer generations, a bounded JSON control codec, authenticated peer roles and explicit FD roles. Bulk immutable metadata may use sealed memfd. Keep internal Android Binder internal.

## Alternatives and consequences

SO_PEERCRED must be interpreted with UID/PID namespace mappings and helper-issued instance credentials; socket permissions alone do not grant arbitrary Android apps access. Reject truncation, excess FDs and unsupported versions. Stream sockets need additional framing; vsock has no advantage; Binder RPC adds coupling. Venus is a separate renderer transport, not this control protocol.

## Evidence and validation

[K07, A10](../SOURCES.md); [SPIKE-003](../SPIKES.md#spike-003), M1.3/M3/M6. Accept after ancillary-data framing, credential and backpressure fault tests on host and Android.
